# Civitatum Inventory — резервное сохранение в Git

Проверенный выпуск 0.4.1 сохранён локальной меткой `v0.4.1` и серверной веткой `codex/releases/v0.4.1`. Полная история с метками находится в `codex/history/v0.4.1` в `Civitatum_Inventory_v0.4.1_Git_History.bundle`. Предыдущие ветки и метки сохранены.

Проверенный выпуск 0.4.0 сохранён отдельной локальной меткой `v0.4.0` и серверной веткой `codex/releases/v0.4.0`. Bundle с историей и обеими метками выпусков находится в `codex/history/v0.4.0` под именем `Civitatum_Inventory_v0.4.0_Git_History.bundle`.

Проверенный выпуск 0.3.0 сохранён коммитом `d6f9b24967f5613483067017819cde5bd5c5bade` и меткой `v0.3.0`. Его содержимое совпадает с ранее выданным архивом исходников. Новые резервные снимки имеют отдельную историю в ветке `codex/checkpoints/civitatum-inventory`.

## Подключение GitHub

Удалённый `origin`: `https://github.com/ManironRafnrun/civitatum_inventory.git`. Приложение GitHub установлено; чтение и реальная запись проверены 10 октября 2026 года. Обычный Git CLI в этой среде не получил учётные данные, поэтому снимки отправляются через подключённое приложение GitHub. GitHub Actions workflow не требуется.

Скрипт автоматически выбирает connector при наличии приватного `.git/civitatum-backup/github-config.json`. В нём находятся адрес репозитория, идентификатор подключения и путь к SDK текущей сессии; токены в исходники не записываются. При обычной авторизации Git этот конфиг не нужен, и используется стандартный `git push`.

Через connector исходники хранятся обычными Git-коммитами и доступны для клонирования. Серверный коммит имеет другой SHA, поскольку его создаёт GitHub. В сообщении указаны локальный коммит и хеш дерева файлов. Перед объявлением успеха скрипт проверяет серверную ветку и точное совпадение всего дерева, включая двоичные ресурсы и права исполняемых файлов.

Ветки:

- `main` — ветка владельца. Её обновления сохраняются; публикация исходников сюда в рамках резервного копирования отклонена автоматической проверкой и требует отдельного разрешения пользователя.
- `codex/civitatum-inventory` — ветка разработки.
- `codex/checkpoints/civitatum-inventory` — снимки каждые 600 секунд активной работы.
- `codex/releases/v0.3.0` — проверенные исходники версии 0.3.0; не передвигать.
- `codex/releases/v0.4.0` — проверенные исходники версии 0.4.0; не передвигать.
- `codex/original-history` — bundle исходной локальной истории с оригинальной меткой `v0.3.0`.
- `codex/history/v0.4.0` — полный bundle локальной истории с оригинальными метками `v0.3.0` и `v0.4.0`.

Текущий набор инструментов подключения не создаёт Git-теги. Поэтому на сервере проверенная версия обозначена отдельной веткой; исходная аннотированная метка сохранена в bundle. Не выдавайте эту ветку за серверный Git-тег.

Проверка текущего сохранения:

```sh
python3 tools/git_checkpoint.py once
python3 tools/git_checkpoint.py status
```

Успех: `REMOTE_VERIFIED` и `remote_verified: true`. Для connector статус содержит `remote_commit` и `source_tree`; для обычного push серверный и локальный коммиты совпадают. Если ветку изменил другой автор, скрипт прекращает отправку до проверки её истории. Force push не применяется.

## Во время работы

```sh
python3 -u tools/git_checkpoint.py watch
```

Запустите этот процесс в отдельном терминале. Он сначала отправляет снимок, затем повторяет сохранение каждые 600 секунд. Неизменившийся снимок повторно проверяется без создания пустого коммита. Скрипт требует Python 3.10+ и Git, работает на Linux и Windows (на Windows вместо `python3` можно использовать `py -3`).

Пока идёт работа, не реже раза в пять минут продлевайте активность из второго терминала:

```sh
python3 tools/git_checkpoint.py heartbeat
python3 tools/git_checkpoint.py status
```

Активность истекает через 20 минут. При истёкшей активности таймер не коммитит чужие или оставленные без сопровождения изменения. Если рабочая среда пропадёт, процесс тоже пропадёт. В следующей сессии его нужно запускать заново; порядок закреплён в `AGENTS.md`.

Перед завершением:

```sh
python3 tools/git_checkpoint.py once
python3 tools/git_checkpoint.py stop
```

Скрипт снимает исходники, ресурсы, тесты, Gradle Wrapper, инструменты и документацию. Сборки, миры и конфиги тестового запуска исключены. Обычный Git index, рабочая ветка и пользовательские staged-файлы не изменяются. Force push не используется. Если отправка не удалась, локальный снимок остаётся, а статус не объявляется успешным.

## Метки выпусков

Метка `v0.4.0` фиксирует проверенный выпуск обновления окон, даров и HUD. Она сохранена в bundle ветки `codex/history/v0.4.0`; серверная ветка с исходниками выпуска — `codex/releases/v0.4.0`.

Метка `v0.3.0` обозначает локальный коммит `d6f9b24967f5613483067017819cde5bd5c5bade`. Она сохранена в bundle. Обычный Git с настроенной авторизацией позволяет отправить её отдельно:

```sh
git push origin refs/tags/v0.3.0
```

Не переставляйте существующую метку. Снимок текущей работы может не компилироваться; проверенные версии сохраняются отдельно после тестов.

## Восстановление из GitHub

```sh
git clone https://github.com/ManironRafnrun/civitatum_inventory.git CivitatumInventory
cd CivitatumInventory
git switch --track origin/codex/checkpoints/civitatum-inventory
```

Это восстанавливает последние отправленные исходники. При восстановлении новой среды таймер и авторизацию нужно настроить заново по `AGENTS.md`: процессы и приватный SDK не хранятся в репозитории.

Для исходной локальной истории извлеките `Civitatum_Inventory_Git_Backup.bundle` из ветки `codex/original-history`; затем следуйте командам ниже.

## Восстановление из bundle

`Civitatum_Inventory_Git_Backup.bundle` содержит историю, исходники, ветки и метку выпуска. В нём нет удалённого URL, авторизации и содержимого `.git/config`.

```sh
git clone Civitatum_Inventory_Git_Backup.bundle CivitatumInventory
cd CivitatumInventory
git remote rename origin recovery-bundle
git remote add origin <адрес-удалённого-репозитория>
```

Путь к bundle при необходимости укажите полностью. Восстановление проверено клонированием: метка выпуска и исходники доступны из созданного репозитория.
